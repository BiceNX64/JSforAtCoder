本マニュアルでは、システム運用やトラブルシューティングにおいて、ログファイルから効率的に情報を抽出・解析するためのCLIコマンドを解説します。

## 📝 想定する擬似ログデータ

コマンドの動作をイメージしやすくするため、以下の2種類のログファイル（それぞれ数万行以上のデータが記録されているものとします）が存在する前提で解説を進めます。

### access.log（Webサーバーのアクセスログを想定）

```
... (以前のアクセス記録) ...
192.168.1.10 - - [25/Apr/2026:10:00:00 +0900] "GET /index.html HTTP/1.1" 200 1024 "-" "Mozilla/5.0"
192.168.1.11 - - [25/Apr/2026:10:05:12 +0900] "GET /images/logo.png HTTP/1.1" 404 512 "[http://example.com](http://example.com)" "curl/7.68.0"
192.168.1.12 - - [25/Apr/2026:10:06:30 +0900] "POST /login HTTP/1.1" 500 256 "-" "Mozilla/5.0"
192.168.1.10 - - [25/Apr/2026:10:07:45 +0900] "GET /api/data HTTP/1.1" 200 2048 "-" "Mozilla/5.0"
... (以降も多数のアクセス記録が続く) ...
```

左から順に、IPアドレス、クライアント識別子、ユーザーID、日時、リクエスト内容（メソッド、パス、プロトコル）、ステータスコード、レスポンスサイズ、リファラ、ユーザーエージェントが記録されています。

### app.log（アプリケーションの動作ログを想定）

```
... (以前の動作記録) ...
2026-04-25 10:00:01 [INFO] System started normally.
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
2026-04-25 10:05:16 [WARN] Retrying database connection...
2026-04-25 10:10:00 [INFO] User login successful. UserID: 123
... (以降も多数の動作記録が続く) ...
```

左から順に、日付、時刻、ログレベル、メッセージ内容が記録されています。

## 1. 🛠️ 基本編：コマンドの役割

ログ解析を行う上で基礎となる重要なコマンドの一覧です。それぞれの特徴を把握しておきましょう。

| コマンド | 主な用途           | 特徴と使い方                                                 |
| -------- | ------------------ | ------------------------------------------------------------ |
| `cat`    | 全体表示           | ファイル内容をすべて画面に出力します。巨大なファイルには不向きです。 |
| `less`   | ページ送り表示     | 1画面ずつ表示します。上下スクロールや`/`での検索が可能です。`q`キーで終了します。 |
| `tail`   | 末尾表示           | 最後の10行（デフォルト）を表示します。最新のログの確認によく使います。 |
| `head`   | 先頭表示           | 最初の10行（デフォルト）を表示します。ログのフォーマット確認に便利です。 |
| `grep`   | 文字列検索         | 指定したパターンに一致する行を抽出します。ログ解析で最も頻繁に使用する強力なコマンドです。 |
| `awk`    | 列ごとの処理       | 空白などで区切られたデータから特定の列を抽出したり、条件で処理したりできます。 |
| `sort`   | 並べ替え           | 行をアルファベット順や数値順に並べ替えます。集計作業の準備として必須です。 |
| `uniq`   | 重複排除とカウント | 連続する重複行を一つにまとめたり、回数を数えたりします。必ず`sort`とセットで使います。 |
| `wc`     | 件数のカウント     | 行数や単語数を数えます。エラーの発生件数を算出する際などに使います。 |
| `cut`    | 指定部分の切り出し | 行から特定の区切り文字で指定した部分を取り出します。シンプルな抽出に便利です。 |

## 2. 🔍 実践編：具体的な使用例

基本コマンドを使って、実際に膨大なログから情報を探し出す例と、その実行結果です。

### 📌 ログの閲覧と監視

最新のログをリアルタイムで監視し続ける 実行コマンド： `tail -f app.log` 出力結果： 実行中は画面が待機状態になり、ログが追記されるとリアルタイムで画面に表示されます。終了するにはキーボードのCtrlとCを同時に押します。 解説： システムを動かしながら、エラーが出ていないか見張る時に必須の操作です。

ログの末尾100行だけを確認する 実行コマンド： `tail -n 100 access.log` 出力結果：

```
192.168.1.55 - - [25/Apr/2026:23:55:01 +0900] "GET / HTTP/1.1" 200 854 "-" "Mozilla/5.0"
... (中略: ファイル末尾の100行分が表示されます) ...
192.168.1.10 - - [25/Apr/2026:23:59:58 +0900] "GET /api/data HTTP/1.1" 200 2048 "-" "Mozilla/5.0"
```

解説： ファイルの末尾から数えて指定した行数分の最新アクセス記録が抽出されます。

ログの先頭50行だけを確認する 実行コマンド： `head -n 50 app.log` 出力結果：

```
2026-04-25 00:00:01 [INFO] Daily log rotation completed.
2026-04-25 00:00:05 [INFO] System started normally.
... (中略: ファイル先頭の50行分が表示されます) ...
2026-04-25 01:23:45 [INFO] Batch processing finished.
```

解説： ファイルの先頭から数えて指定した行数分が抽出されます。見知らぬログファイルを初めて開く際、どのような項目が記録されているかフォーマットを確認するのに便利です。

### 📌 文字列による検索と抽出

エラーログだけを抽出する 実行コマンド： `grep ERROR app.log` 出力結果：

```
2026-04-25 08:12:03 [ERROR] Disk space critically low.
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
... (中略: ファイル内のERRORを含むすべての行が抽出されます) ...
```

大文字・小文字を区別せずに検索する 実行コマンド： `grep -i "error" app.log` 出力結果：

```
2026-04-25 08:12:03 [ERROR] Disk space critically low.
2026-04-25 09:30:10 [WARN] File not found: unexpected error occurred.
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
... (中略: ERROR、Error、errorのいずれかを含むすべての行が抽出されます) ...
```

解説： 大文字小文字の揺らぎがあるメッセージを漏らさず検索する際に有効です。

特定の文字列を含まない行を抽出する（正常な情報ログ以外を見たい時） 実行コマンド： `grep -v "INFO" app.log` 出力結果：

```
2026-04-25 08:12:03 [ERROR] Disk space critically low.
2026-04-25 09:30:10 [WARN] File not found: unexpected error occurred.
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
2026-04-25 10:05:16 [WARN] Retrying database connection...
... (中略: INFOを含まない行がすべて抽出されます) ...
```

エラーが起きた前後の文脈を確認する 実行コマンド： `grep -A 3 -B 3 "Database connection failed" app.log` 出力結果：

```
2026-04-25 10:04:58 [INFO] User login successful. UserID: 456
2026-04-25 10:05:01 [INFO] API request received. Path: /api/users
2026-04-25 10:05:10 [INFO] Executing database query...
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
2026-04-25 10:05:16 [WARN] Retrying database connection...
2026-04-25 10:05:20 [INFO] Reconnection successful.
2026-04-25 10:05:21 [INFO] Query execution resumed.
```

解説： `-A`は後の行、`-B`は前の行を意味し、該当行の前後3行ずつを一緒に表示することで、エラーに至るまでの経緯を追うことができます。

複数のキーワードのいずれかを含む行を検索する 実行コマンド： `grep -E "ERROR|WARN" app.log` 出力結果：

```
2026-04-25 08:12:03 [ERROR] Disk space critically low.
2026-04-25 09:30:10 [WARN] File not found: unexpected error occurred.
2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
2026-04-25 10:05:16 [WARN] Retrying database connection...
... (中略: ERRORまたはWARNを含むすべての行が抽出されます) ...
```

### 📌 特定の条件での絞り込みと件数確認

特定のIPアドレスからのアクセスを抽出する 実行コマンド： `grep "^192.168.1.10" access.log` 出力結果：

```
192.168.1.10 - - [25/Apr/2026:08:15:22 +0900] "GET / HTTP/1.1" 200 512 "-" "Mozilla/5.0"
192.168.1.10 - - [25/Apr/2026:10:00:00 +0900] "GET /index.html HTTP/1.1" 200 1024 "-" "Mozilla/5.0"
192.168.1.10 - - [25/Apr/2026:10:07:45 +0900] "GET /api/data HTTP/1.1" 200 2048 "-" "Mozilla/5.0"
... (中略: このIPアドレスから始まる行がすべて抽出されます) ...
```

解説： 先頭の`^`は行の始まりを意味し、途中に登場する同じ数字の羅列を誤検知しないようにしています。

特定の時間帯（10時台）のアクセスログを抽出する 実行コマンド： `grep "25/Apr/2026:10:" access.log` 出力結果：

```
192.168.1.10 - - [25/Apr/2026:10:00:00 +0900] "GET /index.html HTTP/1.1" 200 1024 "-" "Mozilla/5.0"
192.168.1.11 - - [25/Apr/2026:10:05:12 +0900] "GET /images/logo.png HTTP/1.1" 404 512 "[http://example.com](http://example.com)" "curl/7.68.0"
192.168.1.12 - - [25/Apr/2026:10:06:30 +0900] "POST /login HTTP/1.1" 500 256 "-" "Mozilla/5.0"
192.168.1.10 - - [25/Apr/2026:10:07:45 +0900] "GET /api/data HTTP/1.1" 200 2048 "-" "Mozilla/5.0"
... (中略: 10時台のアクセス記録がすべて抽出されます) ...
```

特定のステータスコード（404）のログを探す 実行コマンド： `awk '$9 == 404 {print $0}' access.log` 出力結果：

```
192.168.1.55 - - [25/Apr/2026:09:12:34 +0900] "GET /favicon.ico HTTP/1.1" 404 128 "-" "Mozilla/5.0"
192.168.1.11 - - [25/Apr/2026:10:05:12 +0900] "GET /images/logo.png HTTP/1.1" 404 512 "[http://example.com](http://example.com)" "curl/7.68.0"
... (中略: ステータスコードが404の行がすべて抽出されます) ...
```

解説： 空白区切りの9番目の列が404と完全に一致する行を出力します。

エラーの発生件数を数える 実行コマンド： `grep ERROR app.log | wc -l` 出力結果：

```
42
```

解説： `|`（パイプ）は、左のコマンドの出力結果を右のコマンドに渡す記号です。grepで抽出した結果の行数をwcで数えることで、エラーログの総件数を一目で確認できます。

## 3. 🚀 応用編：よく使われるテクニック

複数のコマンドをパイプで繋ぐことで、膨大なデータからの高度な解析や集計が可能になります。

### 📌 集計とランキング

アクセス元のIPアドレスをアクセスの多い順にランキング表示する 実行コマンド： `awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10` 出力結果：

```
   1250 192.168.1.10
    842 192.168.1.12
    630 192.168.1.11
    415 192.168.1.55
... (上位10件のIPアドレスとそのアクセス回数が表示されます) ...
```

解説： 1列目を抽出し、ソートして重複を数え、その回数で降順に並べ替え、上位10件を表示します。異常なアクセスを繰り返しているIPがないか探す際によく使われます。

ステータスコードごとの発生回数を集計する 実行コマンド： `awk '{print $9}' access.log | sort | uniq -c` 出力結果：

```
   8500 200
    320 404
     45 500
      2 503
```

解説： どのエラーがどれくらい起きているかの全体像を把握するのに役立ちます。

アクセス先のURL（パス）のランキングを表示する 実行コマンド： `awk '{print $7}' access.log | sort | uniq -c | sort -nr | head -n 10` 出力結果：

```
   3200 /index.html
   1500 /api/data
    840 /login
    512 /images/logo.png
... (上位10件のパスとそのアクセス回数が表示されます) ...
```

エラーが多発している時間帯（分単位）を特定する 実行コマンド： `grep ERROR app.log | cut -d' ' -f2 | cut -d':' -f1,2 | sort | uniq -c | sort -nr` 出力結果：

```
     25 10:05
     12 08:12
      5 14:30
...
```

解説： ログから時刻部分を切り出し、さらに時と分の部分だけにして集計することで、いつ障害が集中したかを特定します。

### 📌 複雑な条件と数値計算

500番台（サーバーエラー）のステータスコードを抽出する 実行コマンド： `awk '$9 >= 500 && $9 < 600 {print $0}' access.log` 出力結果：

```
192.168.1.12 - - [25/Apr/2026:10:06:30 +0900] "POST /login HTTP/1.1" 500 256 "-" "Mozilla/5.0"
192.168.1.55 - - [25/Apr/2026:14:30:12 +0900] "GET /api/status HTTP/1.1" 503 128 "-" "curl/7.68.0"
... (中略: 500番台のエラー記録がすべて抽出されます) ...
```

解説： `awk`の数値比較機能を使って、500から599までのステータスコードを持つ行だけを取り出します。

特定のパスへのアクセスで、かつ404エラーになっているものを探す 実行コマンド： `awk '$7 == "/login" && $9 == 404 {print $0}' access.log` 出力結果：

```
192.168.1.15 - - [25/Apr/2026:11:20:05 +0900] "POST /login HTTP/1.1" 404 512 "-" "Mozilla/5.0"
192.168.1.22 - - [25/Apr/2026:16:45:30 +0900] "POST /login HTTP/1.1" 404 512 "-" "curl/7.68.0"
...
```

レスポンスサイズが1000バイト以上のアクセスを抽出する 実行コマンド： `awk '$10 > 1000 {print $0}' access.log` 出力結果：

```
192.168.1.10 - - [25/Apr/2026:10:00:00 +0900] "GET /index.html HTTP/1.1" 200 1024 "-" "Mozilla/5.0"
192.168.1.10 - - [25/Apr/2026:10:07:45 +0900] "GET /api/data HTTP/1.1" 200 2048 "-" "Mozilla/5.0"
... (中略: レスポンスサイズが1000を超える記録がすべて抽出されます) ...
```

レスポンスサイズの合計を計算する 実行コマンド： `awk '{sum += $10} END {print "Total Bytes:", sum}' access.log` 出力結果：

```
Total Bytes: 15482930
```

解説： 10列目の数値を足し合わせ、最後に合計値を出力します。トラフィック量をざっくり計算するのに使えます。

### 📌 ファイル操作と整形

特定のユーザーIDのログだけを抽出し、調査用の別ファイルに保存する 実行コマンド： `grep "UserID: 999" app.log > user_999_trace.log` 出力結果： 画面には何も出力されず、コマンドを実行したディレクトリに user_999_trace.log という新しいファイルが作成されます。 解説： `>`を使うことで、画面に出力する代わりにファイルへ書き出します。

複数のログファイルから一括で検索する 実行コマンド： `grep -r "UserID: 999" /var/log/app/` 出力結果：

```
/var/log/app/app.log:2026-04-25 10:05:15 [ERROR] Database connection failed. UserID: 999
/var/log/app/app.log.1:2026-04-24 15:20:10 [INFO] User login successful. UserID: 999
...
```

解説： 指定ディレクトリ以下の全ファイルを再帰的に検索し、ファイル名と該当行を表示します。過去のローテートされたログもまとめて探したい時に活躍します。

圧縮された過去のログファイルから特定の文字列を検索する 実行コマンド： `zgrep "ERROR" app.log.2.gz` 出力結果：

```
2026-04-24 23:55:10 [ERROR] Out of memory.
2026-04-24 23:58:22 [ERROR] Database connection timeout.
...
```

解説： `.gz`で圧縮されたファイルを、わざわざ解凍することなく直接検索できるコマンドです。

特定の列を取り出してCSV形式のようにカンマ区切りで出力する 実行コマンド： `awk '{print $1","$7","$9}' access.log` 出力結果：

```
192.168.1.10,/index.html,200
192.168.1.11,/images/logo.png,404
192.168.1.12,/login,500
192.168.1.10,/api/data,200
... (中略: ファイル全体の指定された列がカンマ区切りで出力されます) ...
```

解説： IPアドレス、パス、ステータスコードを抽出してカンマで繋ぎます。この出力をファイルに保存して、表計算ソフトで読み込ませて分析したい時に非常に便利です。
