`while`で定数部分の`N`と毎年インクリメントされる`year`をカウントして、K以上になったときの`year`を出力&`return`でOKです。最初は、$$\text{合計} \approx N(x+1) + \frac{x(x+1)}{2}$$　のような二次方程式を考えてしまったのですが、シンプルにインクリメントしていけば良い問題でした。参考までに二次方程式の解の公式でやろうとするとJavaScriptでは下記のようになりますが、実装するには手間がかかる上に桁溢れのリスクもある、とのことでした。

```javascript
// 数学で解くバージョン（O(1)解法）

function solveMath(N, K) {
    // 解の公式のパーツを計算
    const b = 2 * N + 1;
    const c = 2 * N - 2 * K;
    
    // ルートの中身（判別式） D = b^2 - 4ac
    // a = 1 なので省略しています
    const D = b * b - 4 * c;

    // もしDがマイナスなら解なし（今回はありえないけど念のため）
    if (D < 0) return 0;

    // 解の公式 x = (-b + √D) / 2
    const x = (-b + Math.sqrt(D)) / 2;

    // xは「1.4年後」みたいに小数になるので、切り上げて整数にします
    // (例: 1.1年後なら、答えは2年後になるので ceil を使います)
    const ans = Math.ceil(x);
    
    // ただし、計算結果がマイナスになる場合は0年後（今年達成）
    return ans > 0 ? ans : 0;
}
```



## 🔠 [ABC443-C](https://atcoder.jp/contests/abc443/tasks/abc443_c)

```javascript
// ABC443
// https://atcoder.jp/contests/abc443/tasks/abc443_c
// 2026-01-31

"use strict";
const fs = require('fs');

function Main(input) {
    const args = input.trim().split(/\s+/);
    let cur = 0;
    const next = () => args[cur++];
    const nextNum = () => Number(next());
    const nextBigInt = () => BigInt(next());
    // const lines = input.replace(/\r/g, '').trim().split(/\n/);

    // 👇️ ロジックを記述 👇️

    const N = nextNum();
    const T = nextNum();
    const A = [];
    for (let i = 0; i < N; i++) {
        A.push(nextNum());
    }

    let nextOpenTime = 0; // 次の再開時刻
    let watchTime = 0; // 累積の見ていた時間

    for (let i = 0; i < N; i++) {
        const a = A[i];
        if (nextOpenTime <= a) {
            watchTime = watchTime + a - nextOpenTime;
            nextOpenTime = a + 100
        }
    }
    
    if (nextOpenTime <= T) {
        watchTime += T - nextOpenTime;
    }
    console.log(watchTime)

    // 👆️ ロジックを記述 👆️
}

Main(require("fs").readFileSync(process.platform === 'linux' ? "/dev/stdin" : process.argv[2], "utf8"));
```

「次の再開時刻」と「累積の見ていた時間」を管理すればよい問題で、ここ最近何度も壁になっている計算量とは無縁の問題でした。元々わたしは、他にも、前回の時刻であったり開いているかどうかの真偽値を管理しようとして複雑化しかけてしまったのですが、Excelで各変数をシミュレーションしているうちに、実際には「次の再開時刻」だけあれば十分だと気づくことができました。ポイントとしては、

- 累積の見ていた時間`watchTime`に加算されるのは、次の再開時刻`nextOpenTime`から時刻`a`までのあいだの時間
- 次の再開時刻`nextOpenTime `> 時刻`a` の場合は処理が不要
- 最後の終了時刻の処理

また、反省点としては、

- 配列の`A`と、`for`のなかの`a`を間違えてコードを書いてしまい、頭のなかで混同してしまったためエラーの原因に気づくのに時間を使ってしまいました。このあたりはわかりやすい変数名(`time`など)にしたほうがつまらないエラーが出なかったのではないかと思いました。

- `for`のあとの最終時刻の処理が漏れていてテストケースが通らなかったのですが、`if`なしの`watchTime += T - nextOpenTime`としてテストケースが通ったため提出した結果お手つきをもらってしまいました。ここはもう少し慎重にやるべきでした。

パフォーマンスのスコアとしては期待したほどではなかったのですが、それでもまずは初のABC3完で、C問題を解くことができてほっとしました。次回以降もCが解けるように練習していきたいです。
