「後ろから決めていく」は、具体的には[この図](https://img.atcoder.jp/abc445/c54c58fe4877e457dc58520027e2700f.png)をみながら考えるとわかりやすいです。

```
元々の配列 [2, 4, 7, 5, 5, 6, 7] 
回答の配列 [5, 5, 7, 5, 5, 6, 7]
それぞれのマスに書かれた数字を元々の配列とし、配列の右端(indexが大きい方)からみていきます。

1. 7番目のマスに7が書かれている → `7`で確定(じぶんの番号と書かれた数字が一致し、それ以上動かないため)
2. 6番目のマスに6が書かれている → `6`で確定
3. 5番目のマスに5が書かれている → `5`で確定
4. 4番目のマスに5が書かれている → 移動する5番目のマスにかかれている`5`で確定。
   ここで**マスの移動は右にしかできず、さらに、いまのマス(4)より右のマス(5, 6, 7)はすでに確定済み**、ということがポイントになります。
5. 3番目のマスに7が書かれている → 移動する7番目のマスにかかれている`7`で確定。
6. 2番目のマスに4が書かれている。4番目のマスは、4.で確定したとおり`5`が書かれているので`5`で確定。
7. 1番目のマスに2が書かれている。2番目のマスは、6.で確定したとおり`5`が書かれているので`5`で確定。
```

具体的なコードをみていきます。

```javascript
    const N = nextNum();

```

`const A = [0]`、`const ans = new Array(N + 1).fill(0);`としているのは、indexとマスに書かれた数字を一致させて管理しやすくするためです。

```javascript
    for (let i = N; i >= 1; i--) {
```

この問題のコアとなるロジックはこの部分です。Nから1までデクリメントする`for`ループを用意し、いまのマスとそのマスに書かれた数字が一致すれば`ans`にその数字を入れて(`if`の処理)、一致しない場合は書かれた文字のマス(必ずいまのマスより右になる)の数字を見に行きます(`else`の処理)。

```javascript
    console.log(ans.slice(1).join(" "));
```

最後は、管理しやすくするために入れた配列の最初のゼロを`slice`で落として、残りを`join`して回答を出力します。

この問題を解いているときには、マスが前に戻ることはないという制約を見落としていて、後ろから決めていくということに思い当たりませんでした。前から愚直に辿っていこうとしたもののぐるぐる循環する場合のことを考えたり、計算量が増えそうということを考えて一度辿ったルートを参照する方法を考えたりしてしまったのですが、そのやり方ではうまく行かなかったです。わかってみれば拍子抜けするくらい短くシンプルなコードなので、このあたりは問題を正確に捉えて柔軟に解決できる訓練が必要です。精進します。

## 🔠 [ABC445-C](https://atcoder.jp/contests/abc445/tasks/abc445_c)

```javascript
// ABC445
// https://atcoder.jp/contests/abc445/tasks/abc445_c
// 2026-02-14

"use strict";
const fs = require('fs');

function Main(input) {
    const args = input.trim().split(/\s+/);
    let cur = 0;
    const next = () => args[cur++];
    const nextNum = () => Number(next());
    const nextBigInt = () => BigInt(next());

    // 👇️ Logic here 👇️

    const N = nextNum();
    const A = [0];
    for (let i = 0; i < N; i++) {
        A.push(nextNum());
    }

    const ans = new Array(N + 1).fill(0);

    for (let i = N; i >= 1; i--) {
        if (A[i] === i) {
            ans[i] = i;
        } else {
            ans[i] = ans[A[i]];
        }
    }

    console.log(ans.slice(1).join(" "));

    // 👆️ Logic here 👆️
}

Main(require("fs").readFileSync(process.platform === 'linux' ? "/dev/stdin" : process.argv[2], "utf8"));
```

In this problem, squares 1 to N have a number $A_i$ written on them such that $i \le A_i \le N$. For each square, you follow the sequence of numbers until you stop. The question asks for the final destination of each square. The key point is the constraint "you cannot return to a square with a smaller index," which makes a backward approach (deciding from the end) effective. I tried thinking about it from the beginning and, failing to consider this constraint, I got stuck thinking about infinite loops and ran out of time.

The "deciding from the end" approach is easier to understand by looking at [this diagram](https://www.google.com/search?q=https://img.atcoder.jp/abc445/c54c58fe4877e457dc58520027e2700f.png).

```
Original Array: [2, 4, 7, 5, 5, 6, 7] 
Answer Array:   [5, 5, 7, 5, 5, 6, 7]

Using the original array as the numbers written on each square, we look from the right end (highest index).

1. Square 7 has 7 written on it -> Fixed at 7 (since it matches the index and doesn't move further).
2. Square 6 has 6 written on it -> Fixed at 6.
3. Square 5 has 5 written on it -> Fixed at 5.
4. Square 4 has 5 written on it -> Moves to square 5, which is already fixed at 5. Fixed at 5.
   The key here is that movement is only to the right, and squares to the right (5, 6, 7) are already determined.
5. Square 3 has 7 written on it -> Moves to square 7, which is fixed at 7. Fixed at 7.
6. Square 2 has 4 written on it. Square 4 was fixed at 5 in step 4, so fixed at 5.
7. Square 1 has 2 written on it. Square 2 was fixed at 5 in step 6, so fixed at 5.
```

Let's look at the specific code.

```javascript
    const N = nextNum();
    const A = [0];
    for (let i = 0; i < N; i++) {
        A.push(nextNum());
    }

    const ans = new Array(N + 1).fill(0);
```

Using `const A = [0]` and `new Array(N + 1)` allows for easier management by matching indices with the square numbers.

```javascript
    for (let i = N; i >= 1; i--) {
        if (A[i] === i) {
            ans[i] = i;
        } else {
            ans[i] = ans[A[i]];
        }
    }
```

This is the core logic. We use a `for` loop decrementing from N to 1. If the current square matches the number written on it, we store that number in `ans`. Otherwise, we look up the result for the square pointed to by the number (which is guaranteed to be to the right).

```javascript
    console.log(ans.slice(1).join(" "));
```

Finally, we remove the leading zero used for indexing with `slice` and output the results.

When I was solving this, I missed the constraint that squares never move backward, so it didn't occur to me to solve it from the end. I tried to trace it naively from the front, worried about cycles and high computational complexity, but it didn't work. In hindsight, the code is surprisingly short and simple. I need to train myself to capture problem constraints accurately and solve them flexibly. I will keep practicing.
