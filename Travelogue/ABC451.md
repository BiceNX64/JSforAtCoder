## 🔠 [ABC451-C](https://atcoder.jp/contests/ABC451/tasks/ABC451_c)

```javascript
// ABC451
// https://atcoder.jp/contests/abc451/tasks/abc451_c
// 2026-04-06

"use strict";
const fs = require("fs");

function Main(input) {
  const args = input.trim().split(/\s+/);
  let cur = 0;
  const next = () => args[cur++];
  const nextNum = () => Number(next());
  const nextBigInt = () => BigInt(next());
  // const lines = input.replace(/\r/g, '').trim().split(/\n/);

  // 👇️ ロジックを記述 👇️
  // 1.初期値取り込みと配列準備
  const Q = nextNum();
  const sortedTrees = [];
  const results = [];

  // 2.クエリのループを設定
  for (let i = 0; i < Q; i++) {
    const t = nextNum();
    const h = nextNum();

    // 3.tが1と2でそれぞれ二分探索してそれぞれの処理に適切な位置を見つけてspliceする
    if (t === 1) {
      let left = 0;
      let right = sortedTrees.length;
      while (left < right) {
        let mid = Math.floor((left + right) / 2);
        if (sortedTrees[mid] < h) {
          left = mid + 1;
        } else {
          right = mid;
        }
      }
      sortedTrees.splice(left, 0, h);
    } else if (t === 2) {
      let left = 0;
      let right = sortedTrees.length;
      while (left < right) {
        let mid = Math.floor((left + right) / 2);
        if (sortedTrees[mid] <= h) {
          left = mid + 1;
        } else {
          right = mid;
        }
      }
      sortedTrees.splice(0, left);
    }
    results.push(sortedTrees.length);
  }
  // resultsを出力
  process.stdout.write(results.join("\n") + "\n");

  // 👆️ ロジックを記述 👆️
}

Main(
  require("fs").readFileSync(
    process.platform === "linux" ? "/dev/stdin" : process.argv[2],
    "utf8",
  ),
);
```

全然解けなかったので早々にGeminiに回答例を見せてもらいました。ポイントは、常に木を昇順に並べるように配列の管理を工夫することです。これにより、`h`より低い木を切るときはまとめて削除できます。

1. 初期値取り込みと配列準備

   1. `sortedTrees`で生きている木を管理し、`results`に解答の元となる本数を貯めていく

2. クエリのループを設定

   1. 処理のタイプ`t`(= 1 or 2)と対象となる高さ`h`を受け取る

3. tが1と2でそれぞれ二分探索してそれぞれの処理に適切な位置を見つけてspliceする

   1. `t === 1` の場合(昇順になるように木を追加する)

      `h` 以上の値が最初に現れる挿入位置を探して、その手前に差し込む

   2. `t === 2`の場合(`h`より小さい木を削除する)

      `h` を超える値が最初に現れる削除の境界線 を探して、そこまでの`h` 以下の木を一掃する

   3. それぞれの処理が終わったら、残っている木の本数を`results`に記録する

4. resultsを出力

   1. `console.log()`ではなく`process.stdout.write`

      `console.log()`は呼び出される度に処理をするためクエリが大きいときにはタイムロスが発生する(オーバーヘッドが大きい)。

      一方で、`results.join("\n")`としてひとつの文字列にまとめてから出力すると呼び出すのが1回で済むため時短になる。

      ```javascript
      process.stdout.write(results.join("\n") + "\n");
      ```


今回の場合では、昇順に並べないで素直に端から順に`h`以下の木を探して削除、を行うと最大Q×Q回の処理が発生してしまうため、二分探索のような効率の良い方法が必要となります。`splice`なども今回は処理が間に合いますが実際には「後ろにある要素をすべてずらす」という重い処理を行っているので要素数が多いときには要注意です。

I couldn't solve this at all, so I asked Gemini for an example solution early on. The key point is to manage the array so that the trees are always sorted in ascending order. This allows us to remove all trees lower than `h` at once.

1. **Initial input processing and array preparation**

   1. Use `sortedTrees` to manage living trees and store the tree counts in `results`.

2. **Set query loop**

   1. Receive processing type `t` (= 1 or 2) and the target height `h`.

3. **Binary search and splice for t=1 and t=2**

   1. When `t === 1` (Add a tree while maintaining ascending order): Search for the first insertion position where the value is greater than or equal to `h`, and insert it.
   2. When `t === 2` (Delete trees smaller than `h`): Search for the boundary where values exceed `h`, and clear all trees up to that point.
   3. Record the remaining tree count in `results` after each process.

4. **Output results**

   1. Use `process.stdout.write` instead of `console.log()`. `console.log()` incurs overhead because it processes output every time it's called. By joining all results into a single string with `results.join("\n")` and outputting it once, you save execution time.

      ```javascript
      process.stdout.write(results.join("\n") + "\n");
      ```

In this case, if you simply search for trees below `h` and delete them one by one without sorting, it would result in up to Q × Q operations. Therefore, an efficient method like binary search is necessary. While `splice` works here, it's important to note that it's a heavy operation that shifts all subsequent elements, which can be problematic if the number of elements is very large.
